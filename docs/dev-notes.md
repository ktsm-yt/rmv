# 開発メモ (rmv の仕様と運用の詳細)

利用者向けの説明は README.md と docs/config.md。ここは開発時に読む仕様の詳細。

型は固定のページ (`index.html`)、AI が返すのは markdown 断片だけ。Stop hook が最後の返事を `state/` に書き、ブラウザが 2 秒ごとに取り込む。Low-Load の型 (`N.` 段 / `ⅰ` 項目 / 🔴🟡🟢 / 表 / mermaid / `検証:` `DECIDE:`) を CSS で毎回同じ位置に写す。

1. hook の出力: `state/latest.html` (返事) / `state/latest.json` (`cwd` `session_id` `ts` `terminal`) / `state/history/<ts>-<sid8>.md` (+ `.json`、直近 200 件。静かなプロジェクトも左のプロジェクト列から落ちないように)。`terminal` は Orca 端末の `ORCA_TERMINAL_HANDLE` (Orca 外なら null)。background セッションは daemon を起こした端末の値を継ぐので、`~/.claude/sessions/<pid>.json` で bg 側の `jobId` と同じ `parkedJobId` を持つ対話プロセスを探し、その環境変数の値に付け替える (Claude Code の非公開形式。読めない時は自分の環境変数のまま)。依頼文と許可待ちの key も同じ値を使う
2. server: 本体は `server.ts` (HTTP の口・一覧・送り先の振り分け)。共有の定数・型・state の読み取りは `core.ts`、相手ごとの生死と宛先の調べ方は `peer-herdr.ts` (herdr の pane)・`peer-orca-term.ts` (Orca の端末と Claude のプロセス)・`peer-codex.ts` (Codex の pane と queue)・`peer-orca-bot.ts` (Orca の Bot と判断待ちの知らせ)。どれも repo 直下に置く (自動の起動し直しが直下の `*.ts` だけを見るため)。決まった送り先へ本文・画像・Enter を打つ部分は `terminal.ts`、端末の画面から入力欄の書きかけを読む純粋な関数は `screen.ts` (単体試験は test/screen.test.ts)。口は `/` `/fragment` `/history` (一覧) `/history/<name>` / `/sessions` (外部ツール向けの一覧、読み取りだけ。`/history` と同じ items から live な本体の返事を session ごとに最新 1 件 (subagent の返事は飛ばして次を見る。session の最新の返事が `sub` (ワーカーの pane) ならその session ごと出さない)、`{sid, session, name, cwd, label, head, title, status, ts, live, deliverable}`。`label` = herdr の `pane list` の今の pane 名 (取れない時は meta の `herdr_label`。`/history` の各行にも載り、viewer の札と返事の上の帯が先頭に付ける)、`deliverable` = `terminal && live && !perm && status !== "blocked"` かつ、今走っている Claude の pid ごとの記録に `sessionId === sid` で `status: "waiting"` のものが無い (許可待ち・質問の答え待ちの間は送れない扱い。ps は `claudeTerminals` のキャッシュを使い回す。表示用なので記録が読めない時は fail open)。`prompt` と `root` / `sub` は出さず、ACAO も付けない。`x-rmv-live` は `/history` と同じ。`RMV_CODEX_PANE_BACKENDS` を設定した時だけ、その専用 App Server で会話 ID を一つに確かめられた Codex の pane を末尾に `agent: "codex"` で足す (`peer-codex.ts` の `confirmedCodexPanes`。同じ会話 ID が 2 つの pane に出たらどちらも出さない、承認待ち (`blocked`) は `deliverable: false`)) / `POST /ext/deliver` (外部ツールから端末へ合図、opt-in。Origin が `RMV_EXT_ORIGINS` (`ORIGINS` とは別、未設定なら `/ext/*` は全部 403) に無ければ本文を読む前に 403。本文は `{sid, ticket}` だけで他のキーは 400、ticket は `^\d{8}-\d{6}-\d{6}$`。`historyItems()` で `session_id === sid` の一番新しい本体の entry を引き (無ければ 404、`sub` なら 409)、その session の `curSid` が sid と違えば 409 `stale`、`!terminal || !live` も 409。Orca の端末 (pane 無し) は `live` が `LIVE_TTL` のキャッシュの値なので、打つ直前に `liveTerminals(0)` と `claudeTerminals(0)` で取り直し、記録した handle が無ければ 409。打ち込みは `/send` に `{name, text: <合図のスラッシュコマンド> <ticket>, focus: false, reset: false}` を自分の origin で渡して端末の解決ごと使い回す。ただし内部の `exact` を渡し、`resolveTerminal` の「同じ cwd の別の Claude 端末」への差し替えはさせない (差し替え先は別の会話。HTTP の `/send` は今まで通り差し替える)。さらに内部の `check` (`extCheck`) を渡し、送り先が決まった後 (herdr の pane の追跡の後) で打つ直前に確かめる: (1) その端末 (Orca は env の `ORCA_TERMINAL_HANDLE` が同じで `HERDR_PANE_ID` 無し、herdr は `HERDR_PANE_ID` と `HERDR_SOCKET_PATH` が同じ) の対話 Claude の pid ごとの記録 `~/.claude/sessions/<pid>.json` (`RMV_SESSIONS_DIR` で差し替え) の `sessionId` が sid でなければ 409 `stale`。state/prompt と history は startup・依頼・返事の時しか書かれないので、`/clear`・`/resume` の直後 (最初の依頼まで) はこれでしか見分けられない。Claude Code は会話を切り替えるたびにこの `sessionId` を書き換える (2.1.309 のバイナリから読んだ)。background は `parkedJobId` = bg 側の `jobId` で同じ会話とみなす。ps の失敗・pid が見つからない・記録が読めない時は fail closed で 409 `unverified`。(2) `state/perm` がある・herdr の `agent_status` が `blocked`・pid の記録の `status` が `waiting` (許可待ちと質問の入力待ち) なら 409 `permission pending` (合図の ticket の先頭の数字がダイアログの選択肢になる)。その後、呼んだ側が先に切っていれば (`req.signal.aborted`) 打たない。応答 `{ok, via}`。試験は test/ext-deliver.test.sh。`RMV_CODEX_PANE_BACKENDS` を設定した時だけ、sid が `confirmedCodexPanes` の会話なら端末に打たず `extDeliverCodex` に回す: キャッシュ無しで pane と会話 ID を確かめ直し (違えば 409 `stale`、確かめられなければ 409 `unverified`、`blocked` なら 409 `permission pending`)、rmp スキルの手順書を読む文を `codex queue --remote` に積む (応答 `{ok, via: "codex"}`、登録できたか分からない時は 504。試験は test/ext-deliver-codex.test.sh)) / `/file?p=<絶対パス>` (返事中のファイルを出す。root は `$HOME/` `/private/tmp/` `/tmp/` `/private/var/folders/` `/var/folders/`、拡張子は画像・動画・音声・html・pdf・txt・json だけ、他は 403。html は `content-security-policy: sandbox allow-scripts` 付きで返し、そのページから `/send` を叩けない) / `POST /open` (返事中のパスを Mac の既定アプリで開く。`-R` 無しの open は `.code-workspace` `.xmind` `.xlsx` `.docx` `.pptx` `.csv` `.md` だけ、`reveal` は root 配下なら拡張子不問で Finder 表示) / `POST /send` (赤ペン、下記)。`RMV_STATE_DIR` で `state/` の場所を差し替えられる (テスト用)
   - 行の能力: `/history` の全部の行に `can` (真偽 7 つ)・`peer` (相手の表示名 `Claude Code` / `Codex` / `Orca Bot`)・`delivery` (送り方 `terminal` = 端末へ打つ / `queue` = Codex のキュー / `letter` = Bot へ手紙 / `null` = 送らない) を `history()` の出口で付ける。値は Codex の行が `peer-codex.ts` の `codexPeer`、Bot・許可待ち・知らせの行が `peer-orca-bot.ts` の `botPeer`、残り (Claude Code の会話) が `server.ts` の `claudePeer`。`can` の中身: `send` = 送信欄から送れる / `keys` = 数字キー 1〜5・📎・入力欄を空にして送る (数字キー) が効く / `images` = 画像・動画・PDF を付けられる / `media` = 会話の画像一覧 (`/media`) を出す / `model` = モデル・エフォートの切り替え・`/now`・数字キー 6〜0 / `commands` = `/` の候補 / `alive` = 生死を答える (偽の行は終わっても隠さない)。viewer は種類 (`codex` `bot`) でなくこれで出し分ける (`canOf`)。`can` の無い行は今までの種類の判定から同じ値を作る (merge の直後は新しい index.html を古い server が配る間があるため)。`codex` `codexPane` `bot` `terminal` の欄は消さない (古い画面や他の道具が読む)。札の文字・送れた時の文言・Codex の pane と会話の結び付けは今も種類で分ける
   - 赤ペン: 段・空行で区切った段落・`ⅰ` 項目・表の行をクリックでピン留め、ひとことを書いて [送信] → `orca terminal send` で本文と Enter を分けて元の端末に打ち込み (`--enter` は Claude 端末で 8 秒待つので使わない)。Enter は入力欄 (`inputDraft`、/ext/deliver の書きかけ判定と同じ読み方) に本文が見えてから送り (最大 `RMV_ENTER_WAIT_MS` = 2 秒待つ、読めない画面は 150ms 待って送る)、送った後も欄に残っていれば 1 回だけ送り直して `state/send.jsonl` に `enterRetry` を残す。確認: `bash test/enter-confirm.test.sh`、成功したら `orca terminal switch` でその端末タブへ戻す (switch の失敗は log のみ)。案表 (A〜E) も行をピン留めして選ぶ (『これにする』と「採用: A」は v0.23.0 で廃止)。ピンのひとことに付けた写真 (カードの 📎・欄への貼り付け・ドロップ) は `images` に入れず、本文のそのピンの行の直下に `  📎 <絶対パス>` の行で送る (クリップボードの [Image #N] ではどのピンの写真か届かない。Claude Code はこのパスの行を画像に変えず文字のまま受け、Read で読む。2026-11-22 に Orca 端末で確認)。ピンと全体で合わせて 10 枚まで。Origin が `http://127.0.0.1:<port>` / `http://localhost:<port>` 以外 (無しも) は 403
   - チャット欄: body に `focus: false` を付けた `/send` (送り先の決め方は赤ペンと同じ)。`false` の時だけ `orca terminal switch` を呼ばず viewer に留まる (省略 = 赤ペン = 切り替える)
   - 画像の貼り付け: チャット欄で ⌘V → `POST /paste` (png / jpeg / gif、20 MB まで、Origin 必須) が `state/paste/` に保存し、欄の上に縮小表示。送信時は `/send` の `images` を 1 枚ずつ osascript でクリップボードに載せて Ctrl+V を送り、端末の下書き欄の `[Image #N]` が増えるのを待ってから本文 (パスを文字で送っても Claude Code は画像にしない)。`RMV_OSASCRIPT_BIN` で差し替え可
   - 画像・PDF 一覧 (右下): `GET /media?name=` が返事のセッションの transcript (`RMV_PROJECTS_DIR`、既定 `~/.claude/projects`) に出てくる画像・PDF の絶対パスと、チャット欄から貼った画像 (`state/paste/<session_id>.txt`) を新しい順に最大 60 件。画像は押すと全画面、全画面の間は ← → で前後の画像へ。PDF は別タブ
   - 確認: `bash test/akapen.test.sh` (一時 state と orca stub で動く。`checked N cases` を出す)
3. hook 配線: `settings.local.example.json` の `hooks.Stop` を対象 repo の `.claude/settings.local.json` にマージ
   - subagent (試作): 同じ hook を `hooks.SubagentStop` にも配線。meta に `agent: {type, id}` を足し、history にだけ書く (`latest.*` は本体の返事のまま)。本文は先頭 4000 字 + (以下略)。`/history` の各 entry に `agent` (本体は null。窓口役でない Bot と作業役の端末にも server が付ける。窓口役でない Bot は `bot` と `agent` の両方を持つ)
   - 表示: 本体の返事と混ぜない。プロジェクト列の先頭のタブは「メイン」→「Bot」→「🤖 ワーカー」の 3 択。「Bot」は窓口役でない Bot の返事 (`bot` と `agent` の両方あり) だけ、「🤖 ワーカー」は subagent と作業役の端末の返事 (`agent` だけ) だけのモードに切り替える (`?mode=bots` / `?mode=agents` として URL に残る。知らない値はメイン。localStorage には持たないので開けば既定の本体モード)。一覧・← →・追従・プロジェクト列・chip・送り先はモードの entry だけを見る。「すべて」/「Bot」/「🤖 ワーカー」= そのモードで repo 絞り込み無し、repo 行のクリックでモード内をその repo に絞る
   - Orca の Claude の作業役: `orca orchestration worker-list --limit 100 --full --json` の `resource.ownershipState` が `owned` / `released` の `terminalHandle` (worker-start が新しく作った端末) の Claude の会話を、返事の行も返事待ちの仮の行も `sub: "worker"` にする。`external` / `user_owned` / 知らない値 / `resource` 無しと herdr の pane (`__` 付き) は触らない。見た handle は `state/orca-workers.json` に貯め、Orca が落ちていても起動し直しても一覧から消えてもワーカー側に残す (新しい記録が owned / released 以外になった時だけ外す)。呼ぶのは Bot・subagent・既にワーカーの行を除いて `term_` / `structworker_` の行がある時だけで、5 秒ごと (`RMV_LIVE_TTL_MS`) に裏で取り直す。初めて見る端末がある時だけ最大 2 秒待つ。取れない間に初めて見た端末はメイン。確認: `bash test/orca-worker.test.sh`
   - Bot の判断待ち・完了の知らせ: `orca bot item list --bot <RMV_NOTICE_BOT> --status needs_you` と `--status done,canceled` の item を `botitem-<uid>.<鍵>.md` の行 (`notice: {kind, number, seen}`) にして、`x-rmv-notices` の header が付いた `/history` にだけ足す (`/sessions`・`/ext/deliver` には出さない)。鍵 = 判断待ちは問いの `eventId`、閉じた物は `closedAt`。Bot の最後の発話では分けない (途中経過も『終了: NG』で締める)。閉じた物は `bot item show` の最後の status の `actor` が `owner` (人が閉じた) なら出さない。返事は status の `actor.chatId` の会話で、状態が変わった後 2 分以内の最初の返事 (載るまで最長 2 分待つ)。閉じた物は返事があっても `closeNote` と閉じた時の一言を出す (返事にある文は重ねない)。`RMV_NOTICE_BOT` の Bot の返事が記録に 1 件以上あるか `state/notice-seen.json` が在る (一度 Orca を読めた) 時だけ呼び、15 秒より古ければ (`RMV_NOTICE_TTL_MS`) /history を待たせずに裏で取り直す。取れない間は前の行のまま。開いた印は `POST /notice/seen` が `state/notice-seen.json` (`{since, seen: {uid: 鍵}}`、`since` = 最初に Orca を読めた server の起動時刻で、これより前に閉じた item は出さない) に残す。閉じた物は最後に動いた順に 30 件まで。確認: `bash test/orca-notice.test.sh`
   - subagent の返事はプロジェクト列の冒頭・上部の stamp・チャット欄の送り先の行に `🤖 worker: …` (セッション chip には付けない)。送り先は親の端末なので本体モードと同じ。未読の赤点は本体の返事だけで数える
4. 手で起動: `bun run server.ts` (http://127.0.0.1:4310、`RMV_PORT` で変更可)
   - プロジェクト列 (右端。⇆ で左右を入れ替え、localStorage `rmx.side`): `/history` の全件を repo (cwd の basename) ごとにまとめ、最後に返事した順に「repo 名・最新返事の HH:MM・冒頭 30 字」。先頭の「メイン」= 本体の返事を repo で絞らない (右隣の「Bot」「🤖 ワーカー」は 3. のモード切り替え)。クリックでその repo に絞り、`?repo=crewforce` として URL に残る (直接開いても同じ。照合は完全一致、大文字小文字は無視)。最新追従・← →・chip もその repo 内だけ
     - 終了したものは既定で隠す: `/history` の各 entry の `live` = その `terminal` handle が (a) 今走っている対話 Claude の端末 (`ps` で `claude` プロセスの環境変数 `ORCA_TERMINAL_HANDLE` を集める。daemon / bg-pty-host / bg-spare / `-p` / `--print` は除く) かつ (b) 今の `orca terminal list` (connected かつ writable) にある かつ (c) その端末で最新の本体の返事と同じ cwd (1 端末で順に別 repo を開いた時、前の repo を live にしない)。どちらも 5 秒キャッシュ (`RMV_LIVE_TTL_MS` で変更、`RMV_PS_BIN` で ps を差し替え)。live な entry が 1 つも無い repo、live でないセッションの chip と送り先の行を隠す。選択中の repo・セッション、固定中の送り先、「すべて」は残す。未読の赤点 (☰) は表示中の repo だけで数える
     - 列の末尾の「終了したものも表示 (N)」/「終了したものを隠す」で repo 列・chip・送り先をまとめて切り替え (N は隠れた repo 数、localStorage `rmx.proj.dead`、隠れた repo に未読があれば「・未読あり」)。(b) が取れない時は header `x-rmv-live: unknown` で全 entry `live: true` (fail open)、トグルは出さず全部表示。(a) の ps が失敗した時は (b) だけで判定 (header は `ok`)
   - 端末の状態の印 (送り先の chip の丸と時刻の色、送信欄の下の一覧): 黄の点 = 人の番 (入力待ち・返事が要る)、青のリング = 待つだけ、緑の点 = 閉じてよい、赤の点 = 許可待ち、回るリング = 作業中。入力待ち・静かの会話は、最後の返事の締め `終了: OK / NG (…)` (`/history` の `end`) で分ける。`NG` は括弧の中の語で分け、作業待ちと言い切れる語 (`稼働中` `完了報告待ち` `結果待ち` `実装中` `作業中` `確認中` `直し中` `実行中`) があり、人の番の語 (`決めること` `残タスク` `判断待ち` `返事待ち` `回答待ち` `OK 待ち` `確認待ち`) が無く、締めの手前 (末尾 1500 字) に `**決めること**` `**残タスク**` の段も無い時だけ `work` (作業待ち)、それ以外の `NG` は `ng` (返事が要る。迷う物は人の番の側に倒す)。印を決める順は 返事が要る → 裏で待ち (裏で shell / monitor / subagent が走っている、青のリングが明滅) → 作業待ち (裏で走っている物なし、青のリングが止まったまま) → 閉じてよい。決めること待ちのまま裏で見張りを回している会話は返事が要るの印になる。スマホの下の帯の『待ち』は人の番だけ数える。締めの行を書かない出力スタイルでは今までどおり (入力待ち・静か・裏で待ち)。確認: `bash test/end-wait.test.sh`
     - repo の色: repo 名の hash から決めた色を、プロジェクト列と chip では名前の前の ●、送り先の行では左の 3px の線に出す (同じ色 = 同じ repo)
   - 未読の赤点: そのプロジェクトを最後に選んでいた時より新しい返事がある (repo ごとの既読 ts は localStorage `rmx.seen`、初回は全部既読から)。列を畳んでいても ☰ が赤くなる
   - 列の開閉: ☰。どの幅でも畳んだ細帯で始まる。上の ☰ ＋ ⇆ にマウスを乗せると返事の上に重ねて開く (離すと閉じる。帯を横切るだけでは開かない)。☰ で列として開いた選択は幅 700px 以上でだけ localStorage `rmx.projR` に覚え、700px 未満は開いても返事の上に重なる
   - セッション chip: 返事の上に 1 行、選択中プロジェクトのセッションだけ。「最新」= その中で最後に返事したセッションを追う / 他の chip = そのセッションに固定 (← → と追従もその中だけ)。選択は `?s=<key>` (key = `/history` の `session` = terminal handle か session_id) に残る
   - ← → キー: 履歴の前 (古い) / 次 (新しい)。最新に戻ると自動追従に復帰
